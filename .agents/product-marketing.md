# Agent OS 产品营销上下文

## 产品与受众

Agent OS 是面向同时使用多个 AI 编程 CLI 的开发者、技术负责人和个人工作室的桌面工作台。它不替代模型或 CLI，而是把本地与远程运行、会话、任务、对比、记忆和知识组织成一个可持续工作的系统。

首要受众已经在使用 Claude Code、Codex、Gemini CLI、OpenCode、Pi 等工具，并正在承受终端分散、远程环境重复登录、结果难比较、上下文会丢失和知识难沉淀的问题。

## 核心定位

- 中文：**让每个 Agent 在一个工作台协作，让每次工作持续积累。**
- English: **One workbench for every agent. Continuity for every task.**

支持文案：

- 中文：在本机或远程节点运行 AI CLI，对比交付结果，并把会话沉淀为可召回的记忆和可阅读的知识。
- English: Run AI CLIs locally or on remote nodes, compare their work, and turn sessions into recallable memory and readable knowledge.

## 三条产品支柱

1. **在正确的位置运行 / Run in the right place**：选择本机或已授权远程节点、CLI、模型、目录和权限，不反复复制上下文。
2. **基于过程做判断 / Review with evidence**：会话、运行记录、任务看板和多 Agent 对比让用户审阅过程与交付，而不只看最后一句回答。
3. **让工作持续积累 / Keep what matters**：短小记忆进入 Agent 上下文，体系化知识成为本地 Markdown 资产；二者职责清晰。

定时任务和消息渠道是“让工作持续运行”的扩展能力，不抢占首屏三条主叙事。

## 品牌语气

- 冷静、具体、可信，像成熟开发工具，而不是夸张的 AI 广告。
- 先说用户能完成什么，再说明实现机制。
- 使用主动语态和短句；避免“革命性、无缝、下一代、赋能、全能”等空泛表述。
- 不声称“支持所有 Agent”“完全安全”“Apple 官方签名”或任何未经实测的能力。
- 所有数量、平台、CLI 和兼容性声明必须能从当前源码、构建矩阵或真实制品验证。

## 中英文术语

| 中文 | English | 说明 |
|---|---|---|
| Agent | Agent | 品牌语境保留 Agent，不译为“智能体”作为主导航名 |
| 工作台 | workbench | 统一运行和审阅入口 |
| 会话 | session | 与 CLI 原生会话关联的连续工作记录 |
| 远程节点 | remote node | 受授权的执行设备 |
| 远程托管 | remote hosting | 控制端与受托管端的授权关系 |

| 知识 | knowledge | 面向人阅读的 Markdown 文章 |

| 定时任务 | scheduled task | 单次或 Cron 触发的任务 |
| 消息渠道 | message channel | 飞书等外部消息入口 |
| 提炼 | curate | 从会话提取记忆或知识草稿 |

## 转化目标与信任

- README 和产品站的首要动作：下载当前稳定版。
- 次要动作：查看源码与快速开始。
- 信任证据：Apache-2.0、数据默认本地保存、真实产品截图、公开发布制品与校验信息、明确的 macOS 签名边界。
- 不使用虚构用户数、节省时间、客户评价或性能指标。

## 视觉方向

对象是“持续工作的 Agent 系统”，不是聊天机器人。视觉签名为一条贯穿页面的任务连续性轨迹：任务进入工作台，在本地/远程执行，经对比审阅，最后沉淀为记忆与知识。真实界面是主视觉证据；装饰图形只用于解释连接关系。
