使用前准备

Agent OS 是工作流和运行时管理器，不提供 Claude、Codex 等模型服务本身。开始前请准备至少一个可正常运行的 Agent CLI。

AGENT CLI

安装并登录 CLI

可在 Agent OS 设置中查看、安装、升级和诊断受支持的 CLI；厂商账号授权、订阅与登录仍由对应 CLI 完成。

WORKSPACE

准备工作目录

会话和任务会在你选择的真实目录中运行。代码项目建议先确认 Git 状态，并明确 Agent 的权限模式。

本地优先不等于模型请求永不出机：会话、任务和索引默认保存在本机，但提示词和文件是否发送到外部服务取决于你使用的 CLI、模型和权限配置。

根据操作系统与 CPU 架构选择对应制品。所有链接都指向 v0.3.8 GitHub Release。

首次启动

01

自动发现 CLI

引导页扫描 PATH 与常见安装位置，显示已安装、缺失和异常状态。完成引导后进入工作台。

02

检查设置

打开设置 → CLI 管理，按需执行重新扫描、安装、升级或诊断；远程托管、消息渠道、语言和诊断也在设置中管理。

03

确认 CLI 可用

在终端运行对应 CLI 并完成厂商登录。Agent OS 能启动和管理 CLI，但不会绕过工具本身的授权流程。

创建会话或原生 CLI

左侧第一个入口支持“会话”和“CLI”两种模式，共用 Runtime Host、Agent、模型和工作目录选择。

SESSION

结构化会话

  • 消息与工具事件以对话形式展示。
  • 运行中继续输入会进入持久队列，不覆盖当前回合。
  • 可从历史、搜索结果或任务运行记录重新打开。
CLI / PTY

原生终端

  • 使用原生 PTY 与 xterm 交互。
  • 适合需要完整 ANSI 输出和直接键盘控制的场景。
  • 关闭窗口后，受 Runtime daemon 管理的后台能力不依赖渲染窗口。

任务看板、运行记录与交付

任务保存工作意图、执行环境、计划和审阅状态；每次运行关联真实会话，并保留独立的执行过程与结构化交付物。

01

创建任务

在看板点击“新建任务”，填写标题与提示词，并选择 Runtime Host、Agent CLI、模型、工作目录、权限和会话策略。

02

运行或计划

可仅创建、创建并运行，或配置一次性时间点/Cron、IANA 时区和错过执行策略。暂停、恢复和立即运行都在定时页完成。

03

查看执行过程

任务详情按运行批次保留触发方式、执行阶段和输出事件；重复运行不会覆盖之前的记录。

04

审阅交付物

执行成功后进入 Review。切换到“交付物”查看最终结果，或打开关联会话检查上下文，再由人工确认 Done。

同一工作目录的计划任务会串行执行。计划由目标 Runtime daemon 持有；关闭桌面窗口后，本机或远程节点仍可按计划触发。

COMPARE

多面板对比

并排添加 Web、结构化会话或 CLI 面板，单独发送或批量发送同一问题。

MEMORY

历史与记忆

通过书签打开常用站点并保留站点会话，可把 Web 页面加入对比工作流。

统计与成长

查看会话、消息、Token、活跃趋势、项目与模型使用情况，并浏览成长 Cardex。

一条消息渠道，切换所有已安装 Agent

在设置 → 消息渠道中连接飞书、个人微信、企业微信、Telegram 或 WhatsApp。渠道接入一次后，会自动获得所有已安装且支持结构化聊天 Agent 的统一消息入口。

ONE CONNECTION

连接渠道并确认闭环

配置平台连接信息并启用渠道；确认页面同时显示传输在线、已收到消息和 Agent 回合闭环。访问策略会在消息进入 Agent 前生效。

DYNAMIC AGENTS

在聊天中选择 Agent

发送 /agents 查看实时可用列表，再发送 /use codex、/use claude 等命令切换。

PERSISTENT CONTEXT

切换 Agent，不覆盖原会话

每个 Agent 都绑定自己的持久会话。切回时继续原上下文；统一搜索和长期记忆仍由 Agent OS 管理。只有 /new 会为当前 Agent 主动开启新对话。

COMMANDS

常用消息命令

/agents · /use <agent> · /new · /status · /open · /stop · /help

消息渠道会让外部用户驱动本机 Agent。使用 owner、allowlist 或显式配对限制访问者；未经批准的请求不会进入 Agent，也不会在批准后自动重放。

由受托管端控制边界的远程 Agent

Agent OS 可以托管其他电脑上的 Agent，但控制端不会因此获得整机权限。受托管端负责核验设备，并决定开放哪些能力、Agent 和文件目录。

01

发现设备并发起配对

通过局域网发现或手动地址连接。双方看到短期配对会话、设备名称和身份指纹；凭据不会出现在公开设备列表中。

02

受托管端核验并批准

对方在自己的设备上核对 6 位配对码与设备指纹，再主动批准控制端。未批准前不开放任何 Agent、会话或文件能力。

03

由对方设置能力与目录

受托管端选择允许的能力、Agent 和目录。文件访问按真实路径边界校验，根目录、兄弟目录和符号链接逃逸都会被拒绝。

04

随时暂停或永久撤销

对方可以暂停授权或永久撤销。撤销后不能静默恢复，已有远程视图、会话和事件流会立即停止。

常见问题

为什么 Agent OS 没有自动登录 Claude/Codex？

Agent OS 只负责发现、启动和管理 CLI。厂商账号、订阅、OAuth 或 API Key 授权必须按对应 CLI 的官方流程完成。

macOS 提示无法验证开发者怎么办？

当前 DMG 未做 Apple Developer ID 公证。请在 Finder 中右键 Agent OS 选择“打开”，确认后系统会记住选择。

数据是不是完全不会离开电脑？

会话元数据、任务、索引和统计默认保存在本机；但模型请求是否发送到外部服务由所选 CLI、模型服务商和权限配置决定。

在哪里查看版本更新？

应用会检查 Agent OS GitHub Release。也可查看 更新日志 或直接下载最新制品。

创建任务提示 Runtime Host 不支持调度怎么办？

请确认已升级到 v0.3.8，并完全退出旧版 Agent OS 后重新启动。v0.3.8 已支持 daemon 临时降级时创建任务，同时以单实例运行避免多个版本争抢同一个 Runtime。

为什么消息渠道列表中的平台不能全部启用？

渠道列表同时展示已接入能力与后续入口。请以每个平台旁的实时状态为准；飞书、个人微信、企业微信、Telegram 与 WhatsApp 以各自实时状态、访问策略和平台前置条件为准。
